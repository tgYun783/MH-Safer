# 역할 분장 (v3, 2026-11-02)

주제: 행위 기반 탐지와 예측을 통한 메모리 변조 탐지 알고리즘

## 분담 원칙
- 탐지 알고리즘의 두 축(언제 바뀌었나 / 어떤 값으로 바뀌었나)을 개발자 2명이 하나씩 맡는다.
- 실험 환경(대상 프로그램·변조 주입기·측정)도 개발자가 나눠 만든다. 저수준 메모리 조작은 A, 대상 값의 의미를 아는 쪽 일은 B.
- 탐지 라이브러리 핵심(감시·탐지 알고리즘)은 A·B가 맡고, PM은 그 밖의 개발 — **AI 개발 하네스**(CLAUDE.md, 문서, 스킬, 훅), 빌드·CI, **A·B 결과물 통합**, 이식성 검증 앱, 데모 화면 — 을 맡는다.
- 통합 중 발견한 모듈 내부 버그는 PM이 고치지 않고 담당자(A·B)에게 넘긴다.

## 윤태건 (PM · 개발 하네스 · 발표)
**PM**
- 일정·마일스톤 관리, 주간 회의, 이슈 트래킹(GitHub Issues/Projects)
- 초기 결정 주도: 대상 OS(Linux 권장), 언어, 감시 방식
- 모듈 간 인터페이스(이벤트·판정 형식) 정의와 변경 관리

**개발 하네스 (Claude Code)**
- `CLAUDE.md`(루트): 프로젝트 목적, 폴더 구조, 빌드·테스트 명령, 코딩 규칙, 금지 사항, "끝났다"의 기준
- 모듈별 `CLAUDE.md`: `monitor/`, `detector/`, `bench/` 등 하위 폴더마다 그 모듈의 맥락과 주의점
- `docs/`: 설계(architecture.md), 인터페이스 명세(interface.md), 실험 프로토콜(experiment.md), 결정 기록(decisions.md), 이 역할 문서
- 스킬: 반복 절차를 파일로 — 예) 실험 한 세트 실행·결과 저장, 결과 CSV → 그래프, 주간 진행 보고 작성
- 훅: 어기면 곤란한 규칙을 강제 — 예) 수정 후 테스트 자동 실행, 정답 라벨·원본 실험 데이터 수정 차단, 커밋 전 포맷 검사
- 서브에이전트: 코드 리뷰어, 보고서 문장 리뷰어 같은 고정 역할
- 팀원 온보딩: 하네스 사용법 안내, 팀원이 겪은 문제를 규칙·스킬로 반영(주 1회 정리)

**개발**
- 저장소 골격·빌드(CMake)·CI(테스트 자동 실행)
- `mtd.h` 공개 API 헤더 초안 (A·B와 확정)
- 스킬·훅에 딸린 스크립트 (실험 실행, 결과 → 그래프)
- **통합**: 빌드·링크, 게임에 libmtd 붙이기, 처음부터 끝까지 이어지는 실행 흐름(게임 → 주입기 → 탐지 → 채점), 통합 테스트, CI에서 매일 자동 통합 확인
  - 판정 결합 로직은 B, 모듈 내부 버그 수정은 각 담당자
- 이식성 검증: API 문서만 보고 두 번째 프로그램(예: 인벤토리/잔고 앱)에 libmtd 적용
- 데모 화면 (게임 + 실시간 탐지 알림) — 선택. 5주차에 일이 밀리면 터미널 로그 시연으로 대체

**발표**
- 중간·최종 발표자료, 데모 시나리오, 발표
- 팀원에게 그림·수치 요청 일정 관리, 최종 보고서 통합

## 개발자 A — 감시 계층 + 행위(타이밍) 기반 탐지 + 변조 주입기
- 메모리 변경 감시: 감시 주소 등록, 쓰기 이벤트 수집
  - 후보: `mprotect` + SIGSEGV 핸들러(페이지 단위), 하드웨어 워치포인트(`perf_event_open`/디버그 레지스터), 주기적 스냅샷 비교(기준선)
- 타이밍 탐지: 정상 실행에서 쓰기 주기·쓰기 주체(명령 주소/호출 스택) 프로필을 학습하고 벗어난 쓰기 탐지
- 변조 주입기: 외부 프로세스에서 메모리 쓰기(`process_vm_writev`/`ptrace`)
  - 시나리오: 타이밍 위반형, 값 위반형, 정상과 비슷한 은닉형
  - 주입할 때마다 정답 라벨(시각·주소·값) 기록
- 결과물: 감시 라이브러리, 타이밍 탐지기, 주입기, 감시 방식별 비교 메모

## 개발자 B — 대상 프로그램 + 예측 기반 탐지 + 평가
- 피감시 대상 프로그램: 터미널 지뢰찾기 게임 + 자동 플레이 모드
- 값 예측: 변수별 변화 규칙(증가량 범위, 상·하한, 단조성) → 통계(이동 평균·분산) → 필요하면 경량 학습 모델
- 두 탐지기 판정 결합 로직(OR/AND/점수 합산) 설계·비교
- 평가: 정답 라벨 기반 자동 채점(탐지율·오탐률·탐지 지연), 자원 측정(CPU·RSS·대상 지연), 감시 주소 수에 따른 오버헤드 그래프, "실제로 쓸 만한가" 결론
- 결과물: 대상 프로그램, 예측 탐지기, 결합 모듈, 평가 리포트
