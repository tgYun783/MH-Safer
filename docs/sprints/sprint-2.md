**상태** 초안 · 2026-11-11 작성(PM) · 팀 확인 후 확정
**근거** `docs/plan.md` §4 2주차, `docs/monitoring-design.md` §8(11-11 `mtd.h` v1 확정), PR #10 리뷰 후속

**스프린트 목표**: 탐지기 v1. 감시 엔진·행위 탐지, 예측 탐지가 각각 단독으로 동작하고, 게임에 libmtd가 붙는다.

**스프린트 끝 시연 (11-16 월 회의)**
1. 단위 테스트로 시연: 구간 밖 변조 → behavior alert, 구간 안 규칙 위반 → prediction alert
2. libmtd를 링크한 게임 봇이 10분 연속 실행, 크래시 0, 판이 바뀌어도 감시 등록 수가 늘지 않음(내부 조회 함수 `mtd_test_watch_count()`로 확인 — S2-11)

## 이번 스프린트의 핵심 위험
- **일정**: 백로그를 3일차(11-11)에 작성했다. 남은 기간은 5일이라 선택 항목은 필수 항목을 다 끝낸 뒤에만 한다.
- **내부 인터페이스**: 행위 탐지(우진)와 예측 탐지·규칙 파서(전유정)는 "변수별 규칙 조회" 내부 인터페이스를 공유한다. 이 인터페이스를 11-12까지 정하지 않으면 두 사람이 서로 다른 가정으로 개발한다 → S2-13.
- **감시 수명**: 게임은 판마다 `GameState`를 새로 할당한다(PR #10, 봇 `--speed-ms 0`으로 10분 ≈ 3,470만 판). `mtd_unwatch`가 해제된 메모리 접근 없이 동작해야 통합(S2-06)이 가능하다.
