## 주간 리듬
- **월요일 스프린트 회의 (30~40분)**: 지난 스프린트 리뷰(완료 항목 시연) → 회고(잘된 점·문제·다음에 바꿀 것 각 1개 이상) → 이번 스프린트 계획(목표·백로그 확정)
- **매일 비동기 체크인 (메신저)**: 어제 한 것 / 오늘 할 것 / 막힌 것. 막힌 것은 PM이 당일 처리
- **수요일 중간 점검**: 스프린트 목표 달성 가능성 확인, 안 되면 범위 조정
- 백로그는 `docs/sprints/sprint-N.md`에 쓰고 GitHub Projects 보드와 맞춘다

## 완료 기준 (Definition of Done, 모든 항목 공통)
- 완료 기준(인수 조건)을 모두 만족하고, 확인 방법을 실제로 돌려 봤다
- PR로 `main`에 병합, 다른 팀원 1명 리뷰
- CI 빌드·테스트 통과
- 바뀐 내용이 있으면 해당 폴더 `CLAUDE.md`·`docs/` 갱신

## 백로그 항목 형식
| ID | 항목 | 담당 | 우선순위 | 추정 | 완료 기준 |
|---|---|---|---|---|---|
- ID: `S<스프린트>-<번호>`
- 우선순위: 필수 / 선택 (선택은 필수를 다 끝낸 뒤에만)
- 추정: 작업 시간(h). 한 항목이 8h를 넘으면 쪼갠다
- 완료 기준: 숫자나 예/아니오로 확인할 수 있게 쓴다
