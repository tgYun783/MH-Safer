## 결론 한 줄
`mprotect`+SIGSEGV 쓰기 가로채기는 **같은 프로세스 안의 쓰기만** 잡는다. 외부 변조 도구의 실사용 경로(`/proc/<pid>/mem`, `ptrace`)는 **보호를 무시하고 써지며 대상은 SIGSEGV를 못 받는다.** → 외부 변조 탐지는 **섀도 복사+검사**가 주력, `mprotect`는 내부 쓰기 탐지 보조.

## S1-11 외부 쓰기 경로 × {쓰기 성공?, 대상 SIGSEGV?}
| 경로 | 쓰기 성공 | 대상 SIGSEGV | 쓰는 쪽 결과 | 해석 |
|---|---|---|---|---|
| 프로세스 내부 (기준) | 예 | **예** | — | mprotect가 잡는 유일한 경우 |
| `process_vm_writev` | **아니오** | 아니오 | `ret=-1 errno=14 (Bad address)` | 보호 페이지엔 쓰기 자체가 실패. 공격자 쪽 오류, 대상 무사 |
| `/proc/<pid>/mem` 쓰기 | **예** | **아니오** | `ret=8 errno=0`, 값이 센티넬로 바뀜 | FOLL_FORCE로 보호 무시. **대상은 모름** |
| `ptrace(POKEDATA)` | **예** | **아니오** | `poke=0`, 값이 센티넬로 바뀜 | 보호 무시. 대상은 모름 |

예측(`sprint-1.md` 핵심 위험)과 4/4 경로 모두 일치.

## mtd.h v1(11-11)에 반영할 제안 (S1-13)
1. **주력 = 섀도 복사 + 검사** (S1-12). 정상 변경 구간(`mtd_begin`/`mtd_end`)에서만 섀도 값을 갱신하고, 구간 진입 시·주기적으로 실제 값과 섀도를 비교해 불일치를 탐지. `/proc/mem`·`ptrace` 변조는 값이 바뀌므로 이 비교로 잡힌다.
2. **`mprotect`는 보조**: 프로세스 내부 쓰기(코드 주입, 같은 주소공간 공격) 탐지용. 기본 감시 방식에서 "필수"→"보조"로 내린다.
3. **탐지 지연은 검사 주기에 종속** → 목표(변조 후 100ms)를 만족하려면 주기 ≤ 100ms. S1-12에서 실측 확인 필요.
4. **재무장 비용 주의**: 투명한 mprotect 재무장은 single-step(x86 TF)/`userfaultfd` 필요 — 아키텍처 의존적이고 오버헤드 큼. 보조 용도이므로 v1에서는 단순화.

## S1-12 섀도 복사+검사 결과 (주력 방식 검증)
**코드** `docs/poc/{shadow_target.c,shadow_injector.c,run_shadow.sh}` · 재현: `bash docs/poc/run_shadow.sh`
구성: 불변 변수 `secret`(지뢰배치형, 합법 구간 없음) + 합법 변경 변수 `timer`(tick형, 100ms마다 구간 안 ++). 검사 주기 100ms, `/proc/pid/mem`로 100회 변조.

| 지표 | 결과 | 목표 |
|---|---|---|
| 탐지율 | **100 / 100** | 100/100 |
| 200ms 이내 탐지 | **100 / 100** | 전부 |
| 탐지 지연 | min 0.1 / avg 49.9 / max 103.9 ms | ≤200ms |
| 정상 timer 오탐 | **0건** | 0 |

→ SIGSEGV가 안 나던 `/proc/mem` 변조를 **섀도 불일치만으로 전부** 탐지. 지연 avg≈주기/2, max≈주기+지터 → **탐지 지연 목표(100ms)는 검사 주기 ≤100ms에 종속**. 정상 변경(합법 구간 안 timer++)은 오탐 0 → 행위 기반("구간 밖 변화만 탐지")이 정상 동작. (판정 PASS)

**행위/예측 분담 (확인된 구조)**: 섀도는 합법 변경 구간(`mtd_begin`/`mtd_end`)에서만 갱신 → ① 구간 **밖** 불일치 = 행위 위반(주기 검사, 타이밍), ② 구간 **안** 규칙 위반 = 예측 위반(`mtd_end` 동기 검사, 값). 지뢰배치처럼 구간이 영영 안 열리는 변수는 섀도 고정 → 어떤 변조든 다음 주기에 포착.

## 한계·주의
- 측정은 Docker Desktop의 linuxkit 커널. 실제 배포 리눅스에서 `yama ptrace_scope`가 1 이상이면 `ptrace`/`/proc/mem`은 **CAP_SYS_PTRACE 또는 같은 세션**을 요구 → 변조 난이도는 올라가나 가능하면 결과는 동일.
- `process_vm_writev`가 EFAULT로 실패한 것은 "페이지가 보호 중일 때"에 한함. 공격자가 쓰기 직전 `mprotect`로 RW로 바꾸거나, 애초에 보호 안 된 틈을 노리면 성공할 수 있음 — 그래서도 섀도 비교가 필요.
