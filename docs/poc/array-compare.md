# 배열 비교 오버헤드 (S2-14 → S3-13)

**상태** 측정 완료 · 2026-11-16
**질문** `mine_field`·`cell_state`(각 480바이트)를 바이트 비교하면(11-11 결정, `docs/monitoring-design.md` §8) 검사 1회 비용과 CPU는 얼마인가
**코드** `bench/array_compare.cpp` (실제 libmtd 엔진 사용, `main` 392288c 기준) · 재현:
```bash
scripts/dev.sh bash -lc 'cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j && ./build/bench/bench_array_compare 10'
```

## 방법
- **측정 1 (마이크로)**: 변수 1개 검사 = `memcpy`(실제값 스냅샷) + `memcmp`(섀도 비교). 엔진의 `detect_outside`와 같은 연산. 값이 같아 `memcmp`가 끝까지 읽는 정상 상태(최악 비용) 기준, 200만 회 평균.
- **측정 2 (엔진)**: libmtd 검사 스레드를 T = 50ms로 10초 돌리고 메인 스레드는 잠든 채, 프로세스 CPU 시간(`CLOCK_PROCESS_CPUTIME_ID`)을 잰다. 이 값은 검사 스레드 CPU와 거의 같다. 검사 1회 비용 = CPU 시간 / (경과 시간 / T). 스레드 깨우기·스케줄링 등 주기마다 드는 고정비가 포함된다.
  - 스칼라만: 4개(`timer`·`mines_remaining`·`cells_opened`·`game_state`)
  - GameState 1개: 스칼라 4 + 배열 2 (게임의 실제 구성)
  - GameState 100개: 600변수(배열 200), 확장 여유 확인용

## 결과
**측정일** 2026-11-16 · **환경** GitHub Actions `ubuntu-latest` (Linux 7.0.0-1016-aws x86_64, Intel Xeon 6975P-C, 4 vCPU), g++ 15.2.0, Release · 1회 실행

### 측정 1: 변수 1개 검사 비용
| 크기(바이트) | ns/회 |
|---|---|
| 4 | 7.0 |
| 480 | 13.3 |

### 측정 2: 검사 스레드 CPU (T = 50ms)
| 구성 | 감시 변수 | 배열(480B) | 검사 CPU(%) | 검사 1회(us) |
|---|---|---|---|---|
| 스칼라만 | 4 | 0 | 0.0398 | 19.92 |
| GameState 1개 | 6 | 2 | 0.0396 | 19.81 |
| GameState 100개 | 600 | 200 | 0.0796 | 39.81 |

## 해석
- **배열 바이트 비교 비용은 무시할 수 있다.** 480바이트 검사 1회는 13.3ns로 4바이트(7.0ns)의 약 2배다. 게임 구성에 배열 2개를 더해도 검사 CPU는 0.0398% → 0.0396%로 측정 잡음 안에 있다.
- **검사 1회 비용(~20us)은 변수 비교가 아니라 주기마다 드는 고정비(스레드 깨우기·락·스케줄링)가 대부분이다.** 비교 자체는 6변수에 0.1us 미만(측정 1로 추정)이다.
- **확장 여유**: 600변수(배열 200개)에서 검사 1회 39.8us, CPU 0.08%. 고정비를 빼면 변수당 약 33ns다. 프로젝트 오버헤드 목표(10변수 CPU +10%)와 비교하면 세 자릿수 이상 여유가 있다.
- 결론: 11-11 결정(배열은 바이트 비교, 해시는 alert 표현용으로만)을 성능 때문에 바꿀 이유가 없다. `monitoring-design.md` §3·§8의 배열 검사 오버헤드 항목은 이 문서 수치로 갱신했다.

## 한계
- 클라우드 VM(GitHub Actions)에서 1회 측정. 다른 실행이나 하드웨어에서는 절대값이 달라질 수 있다. 다만 "배열 비교 비용 ≪ 주기 고정비"라는 결론은 측정 1과 측정 2가 함께 뒷받침한다.
- 값이 안 바뀌는 정상 상태 기준이다. 변화가 있어 alert를 만드는 경로(문자열 복사·큐 적재)의 비용은 포함하지 않았다.
